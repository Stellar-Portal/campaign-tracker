# Stellar OS

Stellar's internal platform. A sidebar links its sections: **Campaign overview** (the backlog, from the Campaign Overview sheet), **Tracker** (TikTok campaigns: paste creator links, track plays, likes, comments, shares, spend and cost per view), **Analytics** (`analytics.js`), and the planned **PayPal payouts**, **Creator payments** and **Invoices** (placeholders for now; add them in `NAV` and `SOON` in `app.js`).

- **Front end:** these static files, served by GitHub Pages. No build step.
- **Back end:** Supabase project `StellarCRM`: database, team logins, cover storage, and the `process-links` Edge Function that looks links up through ScrapeCreators.
- **Daily refresh:** the `refresh-stats` Edge Function runs every 5 minutes between 04:00 and 06:55 Copenhagen time (03:00–05:55 in winter). Each run collects the next batch of videos and sounds in active campaigns that don't have today's numbers yet, so no video is paid for twice in a day. Campaigns stop being refreshed 30 days after their end date. "Refresh numbers" on a campaign page runs it for that campaign on demand, skipping anything checked in the last hour.
- **Client links:** "Share with client" on a campaign page creates one private link per artist (`share.html#t=…`). It shows every non-draft campaign for that artist: totals with engagement rate, sounds, songs and countries over a chosen date range, plus the post wall. It never shows budgets, spend, margins or creator payment details. The `share` Edge Function checks the token and returns only those fields; turning the link off makes it stop working immediately. Each link has settings (which tabs, charts, campaigns, creator country and follower counts the client sees); the function leaves out anything switched off, so it never reaches the client's browser. There is no setting for money. "Client view" on a campaign page shows the team the same report with everything on.
- **Campaign Overview sheet:** every campaign with a PO number is written to the "Copy of CAMPAIGN OVERVIEW FY26/27" tab (set by SHEET_GID and SHEET_NAME in the script). Artist + song + PO identify the row; a new campaign takes the first empty "Select" row. Any change to a campaign, its market splits or its creator costs queues it (`campaign_sheet_sync`), and the `sheet-sync` Edge Function sends it within about a minute through an Apps Script web app inside the sheet (`sheets/CampaignOverviewSync.gs`). The tracker owns sections 1–3, Campaign Cost and Margin (only once creator costs are recorded) and the Budget Allocation columns; it never writes invoicing, Comments, the posts/deliverables columns or any cell with a formula. Deleting a campaign leaves its sheet row alone. The web app URL and shared secret live in `private.settings`, never in this repo.
- **Campaign overview page:** the `sheet-sync` function copies every filled-in row of the sheet tab into `overview_snapshot` every 5 minutes (and on "Refresh from sheet"). Rows are matched to tracker campaigns by Artist + Song + PO; matched rows link to the campaign, the rest have "Create", which opens the campaign form filled in from the row (status, client details, dates, price, PO, budget allocations as markets). Saving it makes the tracker keep that row up to date. Invoicing columns are read-only here.
- **Two-way sync:** the script tags each campaign's row with a hidden `stellar_campaign_id` (Developer Metadata), so the row stays linked when it is renamed, sorted or moved; untagged rows still fall back to Artist + Song + PO. On every 5-minute read, `pullEdits` compares each linked row with what the tracker last wrote (`campaign_sheet_sync.sheet_fields`) and copies only the fields changed in the sheet into the campaign: status, artist, song, PO, client details, DRI, start date and duration, price, currency and budget allocations. If the same campaign was also edited in the platform and not sent yet, the platform's version wins and overwrites the row. The result shows on the campaign page as "Updated from the sheet: …" (`sheet_note`). A price change keeps a split entered in % at the same percentages (each market's amount follows the new price, and the new amounts are written back to the sheet); a split entered as amounts keeps its figures. The form saves which one was used in `campaigns.split_mode`.
- **Personal views:** sorting (menu or column headers) and filters on the Campaign overview are saved per person in `user_prefs` (row level security: each person reads and writes only their own row), so nobody changes anyone else's view. The default is most recently added first. Totals are converted to USD with the day's ECB rates; the original currencies show on hover.
- **Analytics:** charts across every campaign in the Campaign overview sheet (revenue by month and region, booked → invoiced → paid with the list of finished campaigns not invoiced, top clients and Major/Indie split, budget by market, revenue per DRI with shared campaigns split equally, margin by deal size) plus tracker performance (views over time, top campaigns, price per 1,000 views). Amounts are converted to USD with ECB rates stored daily in `fx_rates` by the `fx-rates` function. Every chart states how many campaigns it is based on and has a table view. Dates in an "FY26/27" tab are read as April 2026 – March 2027.
- **Trending** (`trending.js`): songs and artists breaking out per country, for Asia, LATAM and the US (`trend_countries`; flip `enabled` or add a row to follow another market). The `chartmetric-sync` Edge Function runs every 5 minutes between 04:00 and 05:55 UTC: it collects the latest Spotify daily Top 200 and Shazam chart per country (`trend_chart_rows`; `trend_fetch_log` makes each run continue where the last stopped), then, for the day's 40 strongest songs, their worldwide momentum from Chartmetric's track stats: Spotify streams and the number of TikTok videos using the song, last 7 days against the 7 before (`trend_track_signals`, 2 calls per song, at most 40 songs a day). `trend_compute_scores()` scores each song per country: chart entries and climbs (up to 40 per chart), Spotify stream growth (up to 30), TikTok video growth (up to 45), a cap of 40 for songs rising on Shazam alone, and a bonus for rising on two or three platforms; the rules are written out in the migration and on the page. Spotify discontinued its Viral charts in May 2026 and Chartmetric's weekly TikTok charts stopped updating then, so neither is used. Artists are ranked by the scores of their songs; an artist's TikTok, Instagram and YouTube audience is loaded from Chartmetric automatically the first time someone opens that platform's tab on the artist page (one call) and kept 30 days (`trend_artist_audience`). Needs the Supabase secret `CHARTMETRIC_REFRESH_TOKEN`.
- **Markets and folders:** markets are the sheet's 16 allocation columns (`markets` table), split by % or by amount. A campaign can get a folder per market automatically, or folders named by hand (e.g. per creative). Every post can sit in one folder; folders never change the campaign's totals. A folder can be hidden from client links (its posts still count, just unnamed) and can have its own client link that shows only that folder's posts and numbers.
- **Access:** only signed-in users whose email is in the `team_members` table can see or change anything. Every table is protected by row level security.

## YouTube
YouTube videos (Shorts or regular) can be pasted next to TikTok links. They're read with Google's official YouTube Data API (free: 10,000 units a day; one call covers up to 50 videos), not ScrapeCreators. Needs the Supabase secret `YOUTUBE_API_KEY`. They reuse the same tables: ids are stored as `yt:<id>` in `posts.tiktok_video_id` / `creators.tiktok_user_id`, with `platform = 'youtube'`. YouTube doesn't publish share counts, so shares stay empty and engagement rate is likes + comments per view.

## Design

The look follows `DESIGN.md`: Apple's design language from [awesome-design-md](https://github.com/VoltAgent/awesome-design-md) (MIT), with Stellar cobalt as the single accent colour and the Stellar logo kept. AI coding tools read that file, so new screens stay consistent; change the Stellar section at the top of it to change the rules.

## Adding a team member

1. Supabase → Authentication → Users → Add user, with their email and a password.
2. Supabase → SQL Editor: `insert into team_members (email, name) values ('name@stellarmusic.dk', 'Name');`

## Artist search
The campaign form's artist search (`artist-search` function) uses Chartmetric: official Spotify artist photos, ranked by monthly listeners, at 1 API credit ($0.01) per search. Each picked artist is saved in `artists` with its Chartmetric id (`cm_artist`), which also identifies them in Trending. If Chartmetric is unavailable (no credits, outage), the search falls back to Deezer automatically.

## If the sheet tab is recreated
The sheet script finds the campaign tab by its name (`SHEET_NAME`), so a tab that is deleted and recreated keeps working as long as it has exactly the same name and the same layout (headers in row 2, data from row 4). The hidden row tags travel with a duplicated tab; on a tab rebuilt by pasting, rows are matched by Artist + Song + PO and re-tagged the next time the platform writes them. If the tab can't be found, the Campaign overview page shows "last refresh failed" with the reason.

## Payouts

**Payouts** replaces the PayPal Payout Sheet. Each campaign page has a team-only **Payouts** tab (`#/c/<id>/payouts`, `payouts.js`); clients never see it (the share function never reads these tables). A campaign's payouts are split into **sections**, one per set of deliverables (e.g. "20x Edits": 20 edits at $50 each = a $1,000 section budget), with one row per creator: handle, who sources and pays them, videos, price per video, total, status (Contacted → Waiting for draft → Drafted → Waiting for payment → Paid, the sheet's c / wd / wp), posted, paid via (PayPal, Wise, bank) and date, and notes. Cells save as you type, like a spreadsheet. "Posted" counts the creator's posts in the tracker (a tick box covers posts the tracker doesn't follow); posted creators move to "Waiting for payment" by themselves. The summary shows the budget invoiced, creator spend, what's left under the spend cap (30% of the budget by default, editable per campaign in `campaigns.spend_cap_percent`), the margin and what's still to pay; creator spend can never go over the campaign budget. **Paste from sheet** imports rows copied from the Google payout sheet (creator, sourced & paid by, per video, total, videos, money sent, posted, notes). The **Payouts** page in the sidebar lists everyone waiting for payment across campaigns (filter by who pays them) and each campaign's spend against its cap and region (Stellar West / Central / East). Tables: `payout_sections`, `payout_rows`; campaign spend in `campaign_summary` now comes from the payout rows.

## Roster
**Roster** (`roster.js`, under Campaigns) is Stellar's list of creators on TikTok, Instagram, YouTube, X and Twitch. Add one by pasting a profile link, a video link or a @handle (with the platform picked for a bare handle) on the Roster page, with ☆ next to a creator in a campaign's creator table, or from Discover. The `roster` Edge Function reads the profile and recent posts and stores followers, median and average views, median likes/comments/shares, engagement rate (per view on TikTok, YouTube and Twitch; per post, of followers, on Instagram and X), posts per week (pinned posts left out), the 12 latest posts with covers, and the profile picture (public `avatars` bucket, because platform picture links expire). Sources and cost per refresh: TikTok 3 ScrapeCreators credits, Instagram 1 (its 12 latest posts), Twitch 1, X 1 (profile numbers only), YouTube free through the official API. Rows are keyed in `creators.tiktok_user_id` as the TikTok id, `ig:<id>`, `yt:<channel id>`, `x:<id>` or `twitch:<id>`. The `roster-refresh` schedule refreshes each roster creator once a week (03:40 UTC). Each creator has a page (`#/creator/<id>`) with these numbers, their campaigns with Stellar, team notes and recent posts. "Unlock insights" loads the Influencers.club profile (`creator-insights` function, 1 credit, kept 60 days; needs the secret `INFLUENCERS_CLUB_API_KEY`): signals, audience reachability, follower growth, demographics, geography and language, brand deals, notable followers and lookalikes. Removing a creator from the roster keeps their campaign history.

## Roster lists and comparison
Roster creators can be grouped into named lists (`roster_lists`, `roster_list_members`), e.g. "Football clubs": **+ New list** on the Roster page, **Add creators** inside a list, or the **Lists** menu on a creator. A list has two views: **Creators** (the usual table) and **Compare**, which ranks the list's creators on one platform at a time: estimated audience in a chosen country (followers × that country's share of their audience), follower growth over 3/6/9/12 months, engagement, median views and real audience (Instagram), each against the list average and the best in the list. The numbers come from the `creator_insight_summary` view over unlocked Influencers.club insights; creators without insights are listed with an Unlock button. A creator opened from a list also shows "Compared with <list>": their rank and the list average for followers, growth, engagement and audience in their top country.

## Navigation
Clicking a creator on the Roster (or in a comparison) opens them in a side panel (`…/c/<id>` added to the address, so Back and links work); ‹ › step through the list, Esc closes it, and "Open full page" opens `#/creator/<id>`. Navigation works per sidebar section. **Back** (top left) goes up one level within the section: from a creator's panel to the list it was opened from, from a campaign to the Tracker, from an edit form to its campaign. It never leaves the section and disappears on the section's first page. **Home**, next to it, jumps straight to the section's first page when you're two or more levels deep. A **back to top** button appears at the bottom right once you've scrolled down a page or the side panel.

## Discover
**Discover** (`discover.js`, `#/discover`) finds new creators through Influencers.club's Discovery API on Instagram, YouTube, TikTok, Twitch and X: **AI search** (a plain-language brief that Influencers.club turns into filters, shown as "AI searched for"), **Lookalike / username search** (creators similar to a @handle or profile link), and **All filters** (location, followers, last post, engagement, gender, language, niche, bio, age, verified, growth, posting frequency, posts, audience age/interests/credibility/location/language/gender, hashtags, captions, average views/likes/comments/downloads, and "creator has"; only the filters a platform supports are shown). Influencers.club's API has no TikTok Shop or Tagged-profiles filter. Results can be added to the roster in one click or used as the start of a lookalike search. The `discover` Edge Function runs searches (0.01 credits per creator returned, 25 per page), keeps every search in `discovery_searches` (a repeat within 24 hours is free; "Recent searches by the team" reopens them) and caches the filter value lists in `ic_dictionary` (free, refreshed monthly).
